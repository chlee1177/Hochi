# FileNest 파일 정리와 로컬 검색 v6.2

폴더를 지정하면 로컬 사전 검사 후 AI가 목적·주제별 폴더, 요약, 태그를 제안합니다. 제안을 검토하고 수정·선택한 파일을 한 번에 정리할 수 있습니다. 슬라이드의 파일명과 폴더명은 예시이며 고정 규칙이 아닙니다.

## Windows 실행

1. Python 3.12 이상과 Tkinter, Python Launcher를 설치합니다.
2. 처음 한 번 file-organizer 폴더의 setup.bat를 실행합니다.
3. start.bat를 실행하고 대상 폴더를 선택합니다.
4. 오른쪽 위 **분석 설정**에서 **Ollama · 내 PC** 또는 **OpenAI · 클라우드**를 선택합니다. Ollama는 아래 설치 절차를 따르며 API 키가 필요 없습니다. OpenAI를 선택하면 API 키를 입력합니다. HOCHI_AI_KEY 환경 변수도 지원하며 키는 파일에 저장하지 않습니다.
5. **AI 분석 시작**을 누릅니다. 분석 단계에서는 원본을 이동하지 않습니다.
6. 분류 제안과 검토 대기 파일을 확인한 다음 **N개 파일 정리**로 이동을 실행합니다.

## Ollama와 Qwen으로 로컬 실행

기본 로컬 모델은 **qwen3.5:27b**입니다. 사용자 PC의 설치 모델에 맞췄으며 텍스트와 이미지를 하나의 모델로 분석할 수 있습니다. RTX 4090에서도 입력 길이와 이미지에 따라 추가 메모리가 필요하며, 실제 추론 속도와 분류 품질은 사용자 PC에서 확인해야 합니다.

1. [Ollama Windows 설치 파일](https://ollama.com/download/windows)을 설치하고 Ollama 앱을 실행합니다.
2. 새 PowerShell을 열고 모델을 다운로드합니다. 최초 다운로드에는 인터넷과 저장 공간이 필요합니다.

```powershell
ollama pull qwen3.5:27b
ollama list
```

3. 파일 정리 앱의 **분석 설정**에서 아래 값을 입력합니다.

| 설정 | 값 |
| --- | --- |
| AI 실행 방식 | Ollama · 내 PC |
| 서버 주소 | http://127.0.0.1:11434 |
| 설치한 모델 | qwen3.5:27b |
| API 키 | 필요 없음 |

4. **연결 확인**을 누른 뒤 **저장**합니다. 연결 확인은 서버와 로컬 모델 설치 정보를 검사하며 파일 내용이나 생성 요청을 보내지 않습니다.
5. 테스트 문서 몇 개를 넣은 폴더를 선택해 **AI 분석 시작 → 결과 검토 → N개 파일 정리**를 실행합니다.

Ollama 앱이 실행되지 않는 경우 앱을 먼저 시작하세요. 명령줄로 서버를 실행하려면 `ollama serve`를 사용할 수 있으며, 이미 앱이 서버를 실행 중이면 별도로 실행할 필요가 없습니다. GPU 사용 상태는 분석 후 `ollama ps`로 확인할 수 있습니다.

이 앱의 Ollama 모드는 내 PC의 루프백 HTTP 주소만 허용하고, cloud 모델과 원격 모델 정보가 반환되는 모델을 거부합니다. OpenAI로 자동 전환하지 않으며 API 키도 Ollama에 보내지 않습니다. 모델 다운로드가 끝난 뒤 로컬 가중치로 분석하므로 OpenAI API 비용은 발생하지 않습니다. PC 전력과 하드웨어 자원은 사용합니다.

[Qwen 3.5 공식 모델 정보](https://ollama.com/library/qwen3.5)를 참고하세요. 프로그램은 연결한 모델의 실제 이미지 지원 여부를 확인한 후 데이터를 전달합니다. 지원 이미지도 개인정보 검사를 위해 기본 검토 대기하며, 파일별 **이 파일의 로컬 분석 허용** 후 내용을 분석합니다. 스캔 PDF의 페이지를 이미지로 변환하는 OCR 기능은 구현하지 않았습니다.

로컬 모드에서도 민감 파일의 자동 분석·이동 제한과 개별 승인 절차를 유지합니다. 승인 버튼은 **이 파일의 로컬 분석 허용**으로 표시하며 이동 승인은 별도입니다. 모델·서버·제공자 변경 시 기존 검토 계획을 비우고 다시 분석합니다.

환경 변수 기본값도 지원합니다. AI 연결 설정은 현재 실행 동안만 유지합니다. 기존 `HOCHI_OLLAMA_MODEL` 환경 변수가 있다면 기본값보다 우선하므로 `qwen3.5:27b`로 수정하거나 제거하세요. 저장 폴더와 후보 대기 기간은 작업 폴더에 따로 저장합니다.

```powershell
$env:HOCHI_AI_PROVIDER = "ollama"
$env:HOCHI_OLLAMA_MODEL = "qwen3.5:27b"
$env:HOCHI_OLLAMA_URL = "http://127.0.0.1:11434"
.\start.bat
```

HOCHI_AI_PROVIDER가 없으면 기존 HOCHI_AI_KEY가 설정된 경우 OpenAI, 그렇지 않으면 Ollama를 기본으로 선택합니다. 이 제공자 선택은 파일 정리 앱에 적용되며 다른 프로젝트의 AI 연결은 바꾸지 않습니다.

로컬 요청은 JSON 스키마로 분류 형식을 지정하고, 지원 모델에서는 thinking 출력을 끕니다. 기본 문맥은 16,384토큰, 생성 한도는 2,048토큰이며 파일을 하나씩 처리합니다. AI 응답에도 기존 경로·분류 검증을 적용합니다. 최초 모델 로딩을 위해 요청별 최대 대기 시간을 180초로 두었으며, 취소는 진행 중인 요청이 끝나거나 시간 초과된 뒤 적용됩니다.

## 화면 구성

2026년 10월 27일 UI 개편: 기획 PPT의 밝은 배경·파란색 강조와 “선택 → 분석 → 제안 → 검토 → 실행” 흐름을 반영했습니다.

- **파일 정리**: 분석한 파일·정리할 파일·검토 대기·이동 완료 수를 표시합니다. 왼쪽 목록에서 현재 파일과 제안 경로를 비교하고 오른쪽에서 요약·태그·검토 사유를 확인합니다.
- **파일 검색**: 검색 방식에서 파일 검색·중복 파일·유사 문서를 선택하고 검색 또는 검사 시작 버튼을 누릅니다.
- **작업 기록**: 최근 작업과 이동 내역을 확인하고 마지막 정리를 되돌릴 수 있습니다.
- **분석 설정**: AI 제공자, Ollama 서버·모델·연결 확인, API 키, 하위 폴더 포함, 내용 분석, 추가 민감 키워드를 관리합니다. 취소하면 변경을 적용하지 않습니다. 키만 변경하면 현재 검토 목록을 유지하지만 제공자·모델·분석 옵션 변경은 다시 분석해야 합니다.
- **더 보기**: 마지막 정리 되돌리기, 결과 폴더 열기, 내 분류 규칙을 제공합니다.
- **버전 관리**: 폴더 감시, 문서 묶음 확인, 최종본 후보·확정·해제와 변경 경고를 제공합니다.

메인 실행 버튼은 단계에 따라 바뀝니다. v3의 분석 직후 자동 이동 버튼은 화면에서 제거하여, 모든 화면상 정리는 분석 결과를 확인한 뒤 별도 실행하도록 바꿨습니다. 내부 자동 정리 엔진과 기존 회귀 테스트는 유지합니다. 추가 UI 패키지 없이 Tkinter로 실행됩니다.

직접 실행:

~~~sh
python -m pip install -r file-organizer/requirements.txt
python file-organizer/app.py
~~~

OpenAI 모드의 기본 모델은 gpt-4.1-mini이며 HOCHI_AI_MODEL로 변경할 수 있습니다. API 비용은 ChatGPT Pro 구독과 별도입니다. 이 앱은 ChatGPT 구독 사용량 연동을 구현하지 않았습니다. 이미지 전송에는 이미지 입력을 지원하는 모델이 필요합니다. 로컬 검색·중복 검사·작업 기록 조회에는 API 키가 필요하지 않습니다.

## 구현 기능

| 기능 | 동작 |
| --- | --- |
| 로컬 사전 검사 | AI 호출 전에 파일명·경로·추출 텍스트의 민감 키워드와 일부 개인정보·인증정보 패턴 검사 |
| 검토 대기 | 감지된 파일은 이름과 내용 모두 외부로 보내지 않고 원래 위치에 유지 |
| 자유로운 분류 | AI가 최대 3단계의 목적·주제별 폴더를 제안. 예시 이름이나 10개 분류에 고정하지 않음 |
| 요약·태그 | 추출한 내용에 대한 요약·태그·분류 이유·AI 자체 확신도를 로컬 SQLite에 저장 |
| 수정과 선택 | 파일별 분류 경로·이동 후 파일명 수정, 실행 대상 포함/제외 |
| 개별 승인 | 검토 후 로컬 이동 승인과 해당 파일의 외부 AI 전송 승인을 별도 처리 |
| 안전한 이동 | 복사 결과 해시를 확인한 뒤 원본 삭제, 이름 충돌 방지, 실패·취소 시 복구 |
| 되돌리기 | 마지막 이동과 검색 색인의 경로 복원. 앱 재시작 후에도 가능 |
| 로컬 검색 | 파일명·분류·요약·태그에서 한국어 문장으로 검색. 검색어는 외부 전송하지 않음 |
| 중복 탐지 | 동일 크기 후보의 SHA-256 해시 비교. 정리된 파일도 비교하며 자동 삭제하지 않음 |
| 유사 문서 | 저장한 요약·태그의 공통 단어를 기준으로 관련 문서 쌍 제시 |
| 작업 기록 | 분석·수정·개별 전송 승인·이동·복구 기록을 로컬에 누적 |

## 검토 화면 사용

- 표의 행을 선택하면 요약, 태그, 분류 이유, 검토 사유를 볼 수 있습니다.
- 일반 파일을 선택하면 **분류·파일명 수정**, 검토 대기 파일을 선택하면 **검토·이동 승인** 버튼을 표시합니다. 분류 경로와 새 파일명, 이동 포함 여부를 수정합니다. 경로는 “분류/주제/세부항목”처럼 최대 3단계입니다.
- 여러 파일을 선택하면 **이동 포함 / 제외** 버튼으로 실행 대상을 바꿀 수 있습니다. 이미 이동한 파일에는 편집 버튼을 표시하지 않습니다.
- 검토 대기 파일은 수정 창에서 직접 검토했다는 이동 승인을 해야 포함할 수 있습니다.
- **이 파일의 AI 전송 허용**(OpenAI) 또는 **이 파일의 로컬 분석 허용**(Ollama)은 선택한 파일 한 개에만 적용됩니다. 이 승인을 해도 이동은 자동 승인되지 않습니다.
- 정리 실행 시 승인하지 않은 검토 대기 파일은 원래 위치에 남기고, 선택된 파일만 이동합니다.
- AI 자체 확신도가 0.75 미만이거나 확신도를 응답하지 않으면 검토 대기로 둡니다. 이 숫자는 측정된 정확도가 아닙니다.
- 미지원 입력은 해당 파일만 건너뛰고 계속 분석합니다. 연결·인증·용량 부족 등 서비스 오류, 잘못된 AI 분류 응답이나 분석 중 원본 변경은 중단하며 전체 이동을 시작하지 않습니다. 기본 결과 폴더는 작업 폴더의 AI_정리이며, 저장·감시 설정에서 변경할 수 있습니다.

## 미지원 파일 확인과 건너뛰기

내용 분석 모드에서는 지원하지 않는 확장자(예: DOC, HWP, PPTX, XLSX, MP3), 추출 실패 문서, 분석 크기 초과 파일, 비어 있는 내용은 **건너뜀**으로 표시하고 다음 파일을 계속 분석합니다. 이름으로 분류한 결과를 내용 분석 성공처럼 취급하지 않습니다. 해당 파일은 원래 위치에 남고 자동 이동 대상에서 제외됩니다.

- 목록의 **건너뜀** 필터로 해당 파일만 확인합니다. 파일을 선택하면 파일명, 확장자 기준 형식, 건너뛴 이유를 표시합니다. 확장자만으로 실제 내용을 확정하지 않습니다.
- **더 보기 → 선택 파일 위치 열기**로 원본 폴더를 확인합니다.
- 분석 결과 중 직접 제외할 파일을 선택하고 **더 보기 → 선택 파일 건너뛰기**를 누르면 이번 정리에서 제외합니다. 여러 파일을 함께 선택할 수 있습니다.
- 필요하면 분류 수정 창에서 경로를 직접 지정하고 이동을 승인할 수 있습니다. 단순한 선택 토글만으로 건너뛴 파일의 이동을 승인하지 않습니다.
- 지원하지 않는 형식도 이름만으로 분류하고 싶다면 분석 설정에서 **지원되는 내용도 분석**을 끄고 다시 분석하세요. 민감 검사·개별 승인 규칙은 유지합니다.

Ollama가 이미지 입력을 지원하지 않거나 명시적인 이미지 형식/디코딩 오류를 반환하면 해당 파일만 건너뜁니다. 개별 이미지 분석 허용 뒤에도 오류를 구분하여 다른 파일의 결과를 유지합니다. 서비스 연결·인증·모델 설치·요청 한도·GPU 메모리 부족 및 잘못된 AI JSON/경로는 미지원 파일로 숨기지 않고 작업 오류로 표시합니다. 현재 OpenAI 공통 연결의 일반 HTTP 오류도 작업 오류로 처리합니다.

건너뛴 상태와 이유는 로컬 색인에 저장합니다. 건너뛰기 때문에 파일을 삭제하거나 다른 폴더로 이동하지 않습니다. 감시 기능은 기존처럼 별도로 동작합니다.

## 저장 위치와 내 분류 규칙

1. **작업 폴더**를 선택한 다음 **저장·감시 설정**을 엽니다.
2. 저장할 디스크와 폴더를 지정합니다. 예: 작업 폴더 `C:\Users\chlee\Downloads`, 저장 폴더 `F:\정리된자료`.
3. 분석 후 파일을 선택하고 **분류·파일명 수정**에서 `수정한내용/수정한내용`처럼 분류 경로를 입력합니다. `/`와 `\`를 모두 사용할 수 있고 최대 3단계입니다.
4. **이 경로 수정을 내 분류 규칙으로 저장**을 선택하면 다음 AI 분석에서 같은 제안 경로를 수정한 경로로 바꿉니다. 예: `대학교/과목명` → `내자료/전공수업`.
5. 실제 이동 위치는 `F:\정리된자료\내자료\전공수업\파일명`입니다. 이동 전에 경로를 확인하고 **N개 파일 정리**를 실행합니다.

**더 보기 → 내 분류 규칙**에서 규칙을 추가·수정·삭제할 수 있습니다. 규칙은 AI 제안 경로 전체가 정확히 일치할 때 한 번 적용하며 와일드카드·접두사 매칭이나 AI 재학습은 아닙니다. 이미 검토 중인 다른 파일이나 이미 이동한 파일의 위치는 자동으로 바꾸지 않습니다. 민감 파일의 개별 검토·이동 승인도 그대로 필요합니다.

작업 폴더의 `.hochi-project.json`에 저장 위치와 대기 기간을 저장합니다. 같은 작업 폴더를 다시 선택하면 복원되며, 기본 설정은 작업 폴더 아래 `AI_정리`입니다. 규칙·색인·복구·버전 기록은 선택한 저장 폴더에 보관합니다. 저장 위치를 바꿔도 기존 파일과 기록을 이전하지 않으므로 이전 작업을 되돌리려면 해당 저장 위치를 다시 선택하세요. 서로 다른 작업 폴더는 같은 저장 폴더를 공유하지 않도록 검사합니다.

저장 폴더는 작업 폴더와 같거나 그 상위일 수 없습니다. 링크·정션을 통한 저장 경로와 분류 경로의 절대 경로·상위 이동은 거부합니다. 다른 디스크로 이동할 때도 기존의 복사 → SHA-256 검증 → 원본 삭제 → 실패 시 복구 방식을 사용합니다.

## 폴더 감시와 최종본 관리

**버전 관리 → 폴더 감시 켜기**로 시작합니다. 앱이 켜져 있고 다른 작업이나 대화상자가 없을 때 작업 폴더와 저장 폴더의 하위 파일을 30초마다 확인합니다. **지금 확인**으로 수동 갱신할 수도 있습니다. 파일 내용 해시를 비교하므로 큰 폴더에서는 디스크 읽기와 확인 시간이 늘어납니다. 한 번의 확인이 끝난 뒤 다음 확인을 수행하며 감시 중에도 취소할 수 있습니다.

- 생성·내용 변경·삭제를 관찰합니다. 내용이 동일한 파일의 이동/이름 변경은 사라진 파일과 새 파일이 각각 하나로 대응할 때만 기존 식별자를 유지합니다. 여러 동일 파일로 대응이 모호하면 확정을 임의로 승계하지 않습니다.
- 내부 관리 파일, 심볼릭 링크·정션, Office 잠금 파일(`~$`), 다운로드/임시 파일(`.tmp`, `.part`, `.crdownload`)은 제외합니다. 읽는 중 변경된 파일은 이번 확인에서 건너뛰고 다음 주기에 재확인합니다.
- 비슷한 이름은 **묶음 제안**으로 표시합니다. 이미 AI 분석한 문서는 저장된 요약·태그의 단어 유사도도 후보로 제시합니다. 자동으로 같은 문서라고 확정하지 않습니다.
- 같은 문서의 파일을 Ctrl/Shift로 여러 개 선택해 **같은 문서로 묶기**를 누릅니다. 잘못 묶었다면 **더 보기 → 선택 파일 묶음에서 분리**를 사용합니다. 분리하면 기존 묶음의 최종본 지정도 해제하므로 다시 확인해 지정하세요.
- **최근 수정본**은 관찰한 내용 변경 시각을 기준으로 표시합니다. 최초 확인 시각이 같으면 파일의 수정 시각을 참고합니다. 실제로 마지막에 읽거나 제출한 파일을 뜻하지 않습니다.
- 묶음에 변경이 없는 기간이 지나면 **최종본 후보**를 표시합니다. 기본 7일이며 **저장·감시 설정**에서 1~365일로 변경할 수 있습니다. 과거 수정 시각을 가진 복사본도 처음 발견한 뒤부터 기다립니다.
- 실제 사용할 파일 하나를 선택하고 **최종본 확정**을 누릅니다. 최신 파일이 아니어도 선택할 수 있습니다. 같은 묶음의 나머지는 **이전 버전**으로 표시하며 삭제하지 않습니다.
- 아직 묶지 않은 새 파일이라도 이름 또는 저장된 요약·태그가 비슷하고 최종본 확정 이후 발견/변경되었다면 **새 버전 후보 확인 필요**를 표시합니다. 자동으로 같은 문서로 합치지는 않으며 사용자가 확인합니다.
- 확정 이후 변경/삭제를 발견하면 재확인 표시를 띄웁니다. 확정 파일 자체의 내용이 바뀌면 이전 확정을 그대로 적용하지 않습니다. **더 보기 → 최종본 확정 해제**로 지정도 취소할 수 있습니다.

태그는 `.hochi-versions.json`에 저장하고 앱 목록·검색에서 보여줍니다. 파일명이나 문서 본문, Windows 탐색기 속성은 변경하지 않습니다. 관찰은 내용 분석이나 자동 분류·이동을 실행하지 않으며 외부 AI에 전송하지 않습니다. AI 요약이 없는 새 파일도 파일명과 버전 태그로 검색할 수 있고, 내용 분류는 별도로 **AI 분석 시작**을 실행합니다.

검색은 **확정 최종본을 우선**하고, 확인된 묶음의 **이전 버전은 기본 제외**합니다. **이전 버전 포함**을 체크하면 함께 검색됩니다. 확정 이후 변경이 발견되면 이전 파일을 조용히 숨기지 않고 경고와 함께 보여줍니다. 후보나 이름 유사도만으로 검색 대상을 제외하지 않습니다. 이는 로컬 검색의 버전 관리이며 RAG 답변 생성은 아닙니다.

앱을 닫으면 감시가 종료됩니다. 다시 실행하거나 작업 폴더를 바꾸면 감시를 다시 켜야 합니다. 다음 확인 때 현재 상태를 비교하지만 앱이 꺼져 있거나 두 확인 사이에 생겼다가 사라진 파일의 모든 이력을 재구성하지는 못합니다. 외부 프로그램에서 열람·제출한 사실을 알아내는 기능이나 문서의 과거 내용을 복원하는 백업 기능은 아닙니다.

## 민감 검사와 내용 분석 범위

기본 로컬 규칙은 주민등록·급여·계약·의료·인증정보·기밀 관련 파일명/경로, .env·개인키 형식, 추출 텍스트에 있는 이메일·전화번호·주민등록번호 형태·일부 API 키·비밀번호 할당 등을 검사합니다. **추가 민감 키워드**에 회사명이나 프로젝트명을 쉼표로 입력할 수 있습니다.

규칙은 오탐과 누락이 있을 수 있습니다. 문서 전체를 보안 검사하거나 모든 개인정보를 판별하는 기능은 아닙니다. 지원 텍스트의 추출 구간만 내용 검사하며 원문 전체를 저장하지 않습니다.

| 형식 | 내용 분석 범위와 기본 처리 |
| --- | --- |
| TXT, MD, CSV, JSON, 코드 등 | 추출한 앞부분 최대 12,000자를 로컬 검사한 뒤 AI 분석 |
| DOCX | 본문 텍스트 앞부분 최대 12,000자 |
| PDF | 32 MiB 이하, 앞 10쪽 중 최대 12,000자 |
| PNG, JPG, WEBP, GIF | 8 MiB 이하. 로컬 OCR이 없어 이미지 내용 검사를 못 하므로 기본 검토 대기, 개별 전송 승인 시 AI 분석 |
| 암호화·스캔 PDF, 텍스트 추출 실패 문서 | 내용 분석 모드에서 건너뜀, 이유 표시·원본 유지 |
| 미지원 형식·내용 분석 한도 초과·빈 내용 | 내용 분석 모드에서 건너뜀. 파일 형식과 이유를 표시하며 다음 파일 분석 계속 |

민감 파일명 자체가 감지되면 그 파일의 내용을 읽어 AI에 보내는 단계로 넘어가지 않습니다. **지원되는 내용도 분석**을 끄더라도 지원 텍스트의 로컬 사전 검사는 수행합니다. 내용 분석 모드에서 이미지 크기 초과·형식 불일치 등은 건너뜁니다. 파일명 분석 모드에서는 개인정보 검사와 개별 승인 원칙을 유지하며 이름으로 분류할 수 있습니다.

## 검색과 데이터 보관

**파일 검색** 화면에서 예를 들어 “클라우드 회의 자료 찾아줘”처럼 입력합니다. 한국어 단어 및 부분 단어를 비교하고 공통 단어에 점수를 주는 검색입니다. 임베딩 기반 의미 검색이나 RAG 답변 생성은 아닙니다. 유사 문서도 요약·태그 기반 단어 유사도이며 확정적인 문서 동일성 판정이 아닙니다.

요약·태그·현재 경로·분류·해시·검토 상태 및 작업 기록은 선택한 저장 폴더의 .hochi-index.sqlite3에 저장됩니다. 재시작 후에도 검색할 수 있고, 이동·복구에 맞춰 경로를 갱신합니다. 분석 이후 사라지거나 크기/수정 시각 또는 내용 해시가 달라진 파일은 오래된 요약으로 검색하지 않습니다. 원문을 수정했다면 다시 분석하세요. 이동 전 편집 중인 계획과 개별 승인 상태는 재시작 후 다시 확인해야 합니다.

기본 검색 결과는 최대 100개, 작업 기록은 최근 100개, 유사 문서 결과는 상위 100쌍입니다. 유사도 계산에서 100개보다 많은 문서에 나타나는 흔한 단어는 후보 생성에 사용하지 않습니다.

요약과 파일명에도 개인정보가 포함될 수 있으므로 색인은 암호화된 보관소가 아닌 **선택 폴더의 로컬 파일**로 취급합니다. 감지되어 보류된 파일은 AI 요약·태그를 만들지 않습니다. API 키와 문서 원문은 색인·로그에 저장하지 않습니다.

## 파일 보호

- 대상 파일 개수나 이동 파일 크기를 50개·8 MiB로 제한하지 않습니다. AI 내용 분석에는 위의 별도 한도가 있습니다.
- 하위 폴더 포함 여부를 선택할 수 있습니다. 심볼릭 링크, Windows 정션, 특수 파일은 제외합니다.
- 결과 폴더는 AI 분석 대상에서 제외합니다. 중복 비교에는 결과 폴더의 실제 파일도 포함하고 내부 관리 파일은 제외합니다.
- 같은 이름은 번호를 붙이며 덮어쓰지 않습니다. 경로 탈출·Windows 예약 이름·절대 경로는 거부합니다.
- 이동은 검증된 복사본을 만든 뒤 원본을 삭제하므로 일시적으로 추가 공간이 필요합니다. Windows의 모든 확장 메타데이터 보존까지 검증한 것은 아닙니다.
- 파일 또는 색인 저장 실패 시 원본 복구를 시도합니다. 복구 위치에 다른 파일이 있거나 정리된 내용이 변경되면 덮어쓰지 않고 중단합니다.
- 선택한 저장 폴더의 .hochi-journal.json은 마지막 작업 복구에 필요합니다. 강제 종료 후에는 되돌리기를 사용하세요. 외부 변경·부분 복사 등으로 자동 복구할 수 없는 경우 원본과 정리 폴더를 확인해야 합니다.
- AI 응답 대기 중 취소는 응답 또는 시간 제한(OpenAI 60초, Ollama 180초) 뒤 적용됩니다.
- 영구 삭제·중복 자동 삭제 기능은 제공하지 않습니다.
