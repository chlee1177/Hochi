# AI 파일 정리와 로컬 검색 v5

폴더를 지정하면 로컬 사전 검사 후 AI가 목적·주제별 폴더, 요약, 태그를 제안합니다. 제안을 검토하고 수정·선택한 파일을 한 번에 정리할 수 있습니다. 슬라이드의 파일명과 폴더명은 예시이며 고정 규칙이 아닙니다.

## Windows 실행

1. Python 3.12 이상과 Tkinter, Python Launcher를 설치합니다.
2. 처음 한 번 file-organizer 폴더의 setup.bat를 실행합니다.
3. start.bat를 실행하고 대상 폴더를 선택합니다.
4. 오른쪽 위 **분석 설정**에서 **Ollama · 내 PC** 또는 **OpenAI · 클라우드**를 선택합니다. Ollama는 아래 설치 절차를 따르며 API 키가 필요 없습니다. OpenAI를 선택하면 API 키를 입력합니다. HOCHI_AI_KEY 환경 변수도 지원하며 키는 파일에 저장하지 않습니다.
5. **AI 분석 시작**을 누릅니다. 분석 단계에서는 원본을 이동하지 않습니다.
6. 분류 제안과 검토 대기 파일을 확인한 다음 **N개 파일 정리**로 이동을 실행합니다.

## Ollama와 Qwen으로 로컬 실행

RAM 64GB / RTX 4090 환경의 시작 모델로 **qwen3:14b**를 권장합니다. [공식 모델 페이지](https://ollama.com/library/qwen3:14b)의 Q4_K_M 배포본은 약 9.3GB이며, 실행에는 모델 외에도 문맥과 작업용 메모리가 추가로 필요합니다. 실제 GPU 처리 속도와 분류 품질은 사용자 PC에서 측정해야 합니다.

1. [Ollama Windows 설치 파일](https://ollama.com/download/windows)을 설치하고 Ollama 앱을 실행합니다.
2. 새 PowerShell을 열고 모델을 다운로드합니다. 최초 다운로드에는 인터넷과 저장 공간이 필요합니다.

```powershell
ollama pull qwen3:14b
ollama list
```

3. 파일 정리 앱의 **분석 설정**에서 아래 값을 입력합니다.

| 설정 | 값 |
| --- | --- |
| AI 실행 방식 | Ollama · 내 PC |
| 서버 주소 | http://127.0.0.1:11434 |
| 설치한 모델 | qwen3:14b |
| API 키 | 필요 없음 |

4. **연결 확인**을 누른 뒤 **저장**합니다. 연결 확인은 서버와 로컬 모델 설치 정보를 검사하며 파일 내용이나 생성 요청을 보내지 않습니다.
5. 테스트 문서 몇 개를 넣은 폴더를 선택해 **AI 분석 시작 → 결과 검토 → N개 파일 정리**를 실행합니다.

Ollama 앱이 실행되지 않는 경우 앱을 먼저 시작하세요. 명령줄로 서버를 실행하려면 `ollama serve`를 사용할 수 있으며, 이미 앱이 서버를 실행 중이면 별도로 실행할 필요가 없습니다. GPU 사용 상태는 분석 후 `ollama ps`로 확인할 수 있습니다.

이 앱의 Ollama 모드는 내 PC의 루프백 HTTP 주소만 허용하고, cloud 모델과 원격 모델 정보가 반환되는 모델을 거부합니다. OpenAI로 자동 전환하지 않으며 API 키도 Ollama에 보내지 않습니다. 모델 다운로드가 끝난 뒤 로컬 가중치로 분석하므로 OpenAI API 비용은 발생하지 않습니다. PC 전력과 하드웨어 자원은 사용합니다.

기본 Qwen3 14B는 **텍스트 모델**입니다. 파일명, TXT, PDF·DOCX의 추출 텍스트를 분석할 수 있지만 이미지 내용은 분석하지 못합니다. 이미지 파일은 기존처럼 검토 대기하며, 내용 분석을 승인하려면 Ollama에서 이미지 입력을 지원하는 로컬 모델을 별도로 설치·선택해야 합니다. 모델의 실제 이미지 지원 여부를 확인한 후 이미지 데이터를 전달합니다. OCR 기능은 추가하지 않았습니다.

로컬 모드에서도 민감 파일의 자동 분석·이동 제한과 개별 승인 절차를 유지합니다. 승인 버튼은 **이 파일의 로컬 분석 허용**으로 표시하며 이동 승인은 별도입니다. 모델·서버·제공자 변경 시 기존 검토 계획을 비우고 다시 분석합니다.

환경 변수 기본값도 지원합니다. UI 설정은 현재 실행 동안만 유지합니다.

```powershell
$env:HOCHI_AI_PROVIDER = "ollama"
$env:HOCHI_OLLAMA_MODEL = "qwen3:14b"
$env:HOCHI_OLLAMA_URL = "http://127.0.0.1:11434"
.\start.bat
```

HOCHI_AI_PROVIDER가 없으면 기존 HOCHI_AI_KEY가 설정된 경우 OpenAI, 그렇지 않으면 Ollama를 기본으로 선택합니다. 이 제공자 선택은 파일 정리 앱에 적용되며 다른 프로젝트의 AI 연결은 바꾸지 않습니다.

로컬 요청은 JSON 스키마로 분류 형식을 지정하고, 지원 모델에서는 thinking 출력을 끕니다. 기본 문맥은 16,384토큰, 생성 한도는 2,048토큰이며 파일을 하나씩 처리합니다. AI 응답에도 기존 경로·분류 검증을 적용합니다. 최초 모델 로딩을 위해 요청별 최대 대기 시간을 180초로 두었으며, 취소는 진행 중인 요청이 끝나거나 시간 초과된 뒤 적용됩니다.

## 화면 구성

2026년 10월 27일 UI 개편: 기획 PPT의 밝은 배경·파란색 강조와 “선택 → 분석 → 제안 → 검토 → 실행” 흐름을 반영했습니다.

- **파일 정리**: 분석한 파일·정리할 파일·검토 대기·이동 완료 수를 표시합니다. 왼쪽 목록에서 현재 파일과 제안 경로를 비교하고 오른쪽에서 요약·태그·검토 사유를 확인합니다.
- **파일 검색**: 검색 방식에서 파일 검색·중복 파일·유사 문서를 선택하고 검색 또는 검사 시작 버튼을 누릅니다.
- **작업 기록**: 최근 작업과 이동 내역을 확인하고 마지막 정리를 되돌릴 수 있습니다.
- **분석 설정**: AI 제공자, Ollama 서버·모델·연결 확인, API 키, 하위 폴더 포함, 내용 분석, 추가 민감 키워드를 관리합니다. 취소하면 변경을 적용하지 않습니다. 키만 변경하면 현재 검토 목록을 유지하지만 제공자·모델·분석 옵션 변경은 다시 분석해야 합니다.
- **더 보기**: 마지막 정리 되돌리기와 결과 폴더 열기를 제공합니다.

메인 실행 버튼은 단계에 따라 바뀝니다. v3의 분석 직후 자동 이동 버튼은 화면에서 제거하여, 모든 화면상 정리는 분석 결과를 확인한 뒤 별도 실행하도록 바꿨습니다. 내부 자동 정리 엔진과 기존 회귀 테스트는 유지합니다. 추가 UI 패키지 없이 Tkinter로 실행됩니다.

직접 실행:

~~~sh
python -m pip install -r file-organizer/requirements.txt
python file-organizer/app.py
~~~

OpenAI 모드의 기본 모델은 gpt-4.1-mini이며 HOCHI_AI_MODEL로 변경할 수 있습니다. API 비용은 ChatGPT Pro 구독과 별도입니다. 이 앱은 ChatGPT 구독 사용량 연동을 구현하지 않았습니다. 이미지 전송에는 이미지 입력을 지원하는 모델이 필요합니다. 로컬 검색·중복 검사·작업 기록 조회에는 API 키가 필요하지 않습니다.

## 구현 기능

| 기능 | 동작 |
| --- | --- |
| 로컬 사전 검사 | AI 호출 전에 파일명·경로·추출 텍스트의 민감 키워드와 일부 개인정보·인증정보 패턴 검사 |
| 검토 대기 | 감지된 파일은 이름과 내용 모두 외부로 보내지 않고 원래 위치에 유지 |
| 자유로운 분류 | AI가 최대 3단계의 목적·주제별 폴더를 제안. 예시 이름이나 10개 분류에 고정하지 않음 |
| 요약·태그 | 추출한 내용에 대한 요약·태그·분류 이유·AI 자체 확신도를 로컬 SQLite에 저장 |
| 수정과 선택 | 파일별 분류 경로·이동 후 파일명 수정, 실행 대상 포함/제외 |
| 개별 승인 | 검토 후 로컬 이동 승인과 해당 파일의 외부 AI 전송 승인을 별도 처리 |
| 안전한 이동 | 복사 결과 해시를 확인한 뒤 원본 삭제, 이름 충돌 방지, 실패·취소 시 복구 |
| 되돌리기 | 마지막 이동과 검색 색인의 경로 복원. 앱 재시작 후에도 가능 |
| 로컬 검색 | 파일명·분류·요약·태그에서 한국어 문장으로 검색. 검색어는 외부 전송하지 않음 |
| 중복 탐지 | 동일 크기 후보의 SHA-256 해시 비교. 정리된 파일도 비교하며 자동 삭제하지 않음 |
| 유사 문서 | 저장한 요약·태그의 공통 단어를 기준으로 관련 문서 쌍 제시 |
| 작업 기록 | 분석·수정·개별 전송 승인·이동·복구 기록을 로컬에 누적 |

## 검토 화면 사용

- 표의 행을 선택하면 요약, 태그, 분류 이유, 검토 사유를 볼 수 있습니다.
- 일반 파일을 선택하면 **분류·파일명 수정**, 검토 대기 파일을 선택하면 **검토·이동 승인** 버튼을 표시합니다. 분류 경로와 새 파일명, 이동 포함 여부를 수정합니다. 경로는 “분류/주제/세부항목”처럼 최대 3단계입니다.
- 여러 파일을 선택하면 **이동 포함 / 제외** 버튼으로 실행 대상을 바꿀 수 있습니다. 이미 이동한 파일에는 편집 버튼을 표시하지 않습니다.
- 검토 대기 파일은 수정 창에서 직접 검토했다는 이동 승인을 해야 포함할 수 있습니다.
- **이 파일의 AI 전송 허용**(OpenAI) 또는 **이 파일의 로컬 분석 허용**(Ollama)은 선택한 파일 한 개에만 적용됩니다. 이 승인을 해도 이동은 자동 승인되지 않습니다.
- 정리 실행 시 승인하지 않은 검토 대기 파일은 원래 위치에 남기고, 선택된 파일만 이동합니다.
- AI 자체 확신도가 0.75 미만이거나 확신도를 응답하지 않으면 검토 대기로 둡니다. 이 숫자는 측정된 정확도가 아닙니다.
- AI 분석 도중 오류가 나면 전체 이동을 시작하지 않습니다. 결과 폴더 이름은 AI_정리입니다.

## 민감 검사와 내용 분석 범위

기본 로컬 규칙은 주민등록·급여·계약·의료·인증정보·기밀 관련 파일명/경로, .env·개인키 형식, 추출 텍스트에 있는 이메일·전화번호·주민등록번호 형태·일부 API 키·비밀번호 할당 등을 검사합니다. **추가 민감 키워드**에 회사명이나 프로젝트명을 쉼표로 입력할 수 있습니다.

규칙은 오탐과 누락이 있을 수 있습니다. 문서 전체를 보안 검사하거나 모든 개인정보를 판별하는 기능은 아닙니다. 지원 텍스트의 추출 구간만 내용 검사하며 원문 전체를 저장하지 않습니다.

| 형식 | 내용 분석 범위와 기본 처리 |
| --- | --- |
| TXT, MD, CSV, JSON, 코드 등 | 추출한 앞부분 최대 12,000자를 로컬 검사한 뒤 AI 분석 |
| DOCX | 본문 텍스트 앞부분 최대 12,000자 |
| PDF | 32 MiB 이하, 앞 10쪽 중 최대 12,000자 |
| PNG, JPG, WEBP, GIF | 8 MiB 이하. 로컬 OCR이 없어 이미지 내용 검사를 못 하므로 기본 검토 대기, 개별 전송 승인 시 AI 분석 |
| 암호화·스캔 PDF, 텍스트 추출 실패 문서 | 내용 검사 불가로 검토 대기 |
| 미지원 형식·내용 분석 한도 초과 | 이름·경로 검사 후 파일명으로만 AI 분석. 근거를 화면에 표시 |

민감 파일명 자체가 감지되면 그 파일의 내용을 읽어 AI에 보내는 단계로 넘어가지 않습니다. **지원되는 내용도 분석**을 끄더라도 지원 텍스트의 로컬 사전 검사는 수행합니다. 이미지는 크기·형식에 따라 이름만 분석될 수 있고, 서비스가 지원하지 않는 애니메이션 등은 API가 거부할 수 있습니다.

## 검색과 데이터 보관

**파일 검색** 화면에서 예를 들어 “클라우드 회의 자료 찾아줘”처럼 입력합니다. 한국어 단어 및 부분 단어를 비교하고 공통 단어에 점수를 주는 검색입니다. 임베딩 기반 의미 검색이나 RAG 답변 생성은 아닙니다. 유사 문서도 요약·태그 기반 단어 유사도이며 확정적인 문서 동일성 판정이 아닙니다.

요약·태그·현재 경로·분류·해시·검토 상태 및 작업 기록은 AI_정리/.hochi-index.sqlite3에 저장됩니다. 재시작 후에도 검색할 수 있고, 이동·복구에 맞춰 경로를 갱신합니다. 분석 이후 사라지거나 크기/수정 시각이 달라진 파일은 오래된 요약으로 검색하지 않습니다. 원문을 수정했다면 다시 분석하세요. 이동 전 편집 중인 계획과 개별 승인 상태는 재시작 후 다시 확인해야 합니다.

기본 검색 결과는 최대 100개, 작업 기록은 최근 100개, 유사 문서 결과는 상위 100쌍입니다. 유사도 계산에서 100개보다 많은 문서에 나타나는 흔한 단어는 후보 생성에 사용하지 않습니다.

요약과 파일명에도 개인정보가 포함될 수 있으므로 색인은 암호화된 보관소가 아닌 **선택 폴더의 로컬 파일**로 취급합니다. 감지되어 보류된 파일은 AI 요약·태그를 만들지 않습니다. API 키와 문서 원문은 색인·로그에 저장하지 않습니다.

## 파일 보호

- 대상 파일 개수나 이동 파일 크기를 50개·8 MiB로 제한하지 않습니다. AI 내용 분석에는 위의 별도 한도가 있습니다.
- 하위 폴더 포함 여부를 선택할 수 있습니다. 심볼릭 링크, Windows 정션, 특수 파일은 제외합니다.
